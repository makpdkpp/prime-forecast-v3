# รายงานตรวจสอบความถูกต้อง Admin Dashboard

วันที่ตรวจสอบ: 11 สิงหาคม 2026
หน้าที่ตรวจสอบ: `/admin/dashboard`
ฐานข้อมูลทดสอบ: `prime_forecast_v3_test`

## 1. ขอบเขตและความปลอดภัย

- ใช้ฐาน MySQL ทดสอบแยกจากฐานเดิม `prime_sale`
- Reset เฉพาะฐาน `prime_forecast_v3_test`
- ฐานเดิมไม่ได้ถูก reset แก้ไข หรือนำข้อมูลจำลองไปปะปน
- ข้อมูลจำลองเป็น deterministic fixture จึง reset แล้วได้ผลลัพธ์เดิมทุกครั้ง

## 2. นิยามการคำนวณที่ใช้

- ปีงบประมาณอ้างอิง `transactional.fiscalyear`
- Forecast รวมเฉพาะโครงการที่ `deleted_at IS NULL`
- ไตรมาสอ้างอิงวันที่สถานะล่าสุด และใช้ `contact_start_date` เมื่อยังไม่มีสถานะ
- โครงการที่ไม่มีสถานะแสดงเป็น `ยังไม่ระบุสถานะ` เพื่อให้ยอดสถานะรวมตรงกับ Forecast KPI
- Target เป็นเป้ารายปี แม้กำลังกรองรายไตรมาส และระบุในกราฟว่า `Target รายปี`
- Win สะสมและ Drill-down ใช้ช่วงสะสมเดียวกัน

## 3. ชุดข้อมูลจำลอง

- ผู้ใช้: Admin 1, Team Admin 1, Sales 4
- ทีม: Alpha, Beta, Gamma
- โครงการปี 2026 ที่ใช้งาน: 20
- โครงการ Soft Delete: 1 มูลค่า 999,000 บาท
- โครงการไม่มีสถานะ: 1 มูลค่า 70,000 บาท
- มีข้อมูลครบทั้ง 6 สถานะ ทุกไตรมาส หลายทีม บุคคล ลูกค้า และโซลูชัน
- มีกรณีวันที่ติดต่อข้ามปี แต่ปีงบประมาณเป็น 2026
- โครงการปีงบประมาณ 2025: 13 โครงการ ครบ Q1–Q4 และมีกรณีวันที่กิจกรรมอยู่ในปี 2026 เพื่อยืนยันว่า Filter ใช้ fiscal year จริง

## 10. สรุป

Admin Dashboard ผ่านเกณฑ์ความถูกต้องสำหรับ fixture ที่กำหนด: KPI, กราฟทั้ง 8 ตัว, Filter ปี/ไตรมาส, Breakdown, Soft Delete, ไม่มีสถานะ และ Drill-down สามารถ reconcile กันได้ทั้งหมด

ขอบเขตของรายงานนี้ครอบคลุมเฉพาะ Admin Dashboard; Team Admin Dashboard ยังไม่ได้เปลี่ยนมาใช้สูตรกลางชุดใหม่นี้
